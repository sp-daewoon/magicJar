MagicJar 자동매매 코드 점검 리포트

자동매매가 시세를 받아 전략을 평가하고, 리스크 게이트를 통과한 뒤 실제 주문과 체결 반영까지 이어지는 전체 길을 초보 개발자도 따라갈 수 있게 정리했습니다. 2026-05-25 추가 패치로 P1 안전장치와 REAL/MOCK 분리 핵심 지점도 반영했습니다.

한눈에 보는 결론

4 P1급 안전 이슈를 처리했습니다. 손실 제한, 체결 중복, 주문 누락, 0 수량/가격 방어가 핵심입니다.
분리 시세/캔들은 REAL 고정 정책을 유지하고, 주문·잔고·포지션·리스크는 MOCK/REAL을 분리하도록 보강했습니다.
통과 Gradle 핵심 테스트, batch/strategy 테스트, 프론트 타입체크와 프론트 전체 테스트가 통과했습니다.
관찰 CPU budget과 DSL 산술 우선순위는 별도 P2 개선 후보로 남겨두는 것이 좋습니다.

이번 패치 결과

실전/모의 혼선과 주문 안전장치 관점에서 실제 코드에 반영한 내용입니다.

P1 주문 안전장치

일일 손실 제한은 체결 이력을 평균단가 방식으로 재계산하고, 잘못된 가격·0 수량·보유 없는 SELL은 주문 전 차단합니다.

REAL 체결 동기화 게이트

REAL 주문은 KIS 당일 체결조회와 DB backfill이 성공해야 다음 단계로 갑니다. 조회·저장·손익/포지션 조회 실패 시 KIS_EXECUTION_SYNC_STALE로 차단합니다.

주문 누락 방지

Redis 멱등성 장애는 조용히 버리지 않고 거절 주문/audit 경로로 남깁니다. 체결 event id에는 가격까지 포함해 부분체결 중복 오탐을 줄였습니다.

REAL/MOCK 분리

런타임 모드 파서를 공통화하고, 포지션 unique key를 user+code+source로 바꿔 실전/모의 포지션이 서로 덮어쓰지 않게 했습니다.

REAL/MOCK 점검 결과

사용자 정책: WS 시세와 캔들값은 REAL, 그 외 주문·잔고·포지션·리스크는 MOCK/REAL 각각 분리.

REAL 고정 유지

시세 WebSocket, REST 현재가/호가, 캔들 refresh, batch 시장 데이터는 REAL 자격증명 기준 흐름으로 확인했습니다.

모드별 분리 보강

주문 라우터, 수동 주문 precheck, reconcile, 포지션 조회, 자본 snapshot, KIS 키 변경 이벤트가 공통 파서와 계좌 타입별 key를 사용합니다. REAL 모드의 일일손익 cache는 stale 방지를 위해 우회합니다.

남은 구조 리스크

KisWebSocketBridge는 시세 구독과 체결통보 구독을 한 클래스에서 함께 다룹니다. 정책은 맞췄지만 장기적으로 세션/클래스 분리를 추천합니다.

초보 개발자용 읽는 법

입력: 시장 데이터

KIS에서 들어오는 실시간 가격을 캔들로 묶고, 캔들이 닫히면 Kafka 이벤트로 다음 단계에 넘깁니다.

판단: 전략과 리스크

전략 DSL이 BUY/SELL/HOLD를 만들고, 리스크 게이트가 실제 주문으로 보내도 되는지 마지막으로 검사합니다.

실행: 주문과 체결

주문 라우터가 멱등성, 거래 모드, 킬스위치를 재검사한 뒤 KIS에 주문을 넣고 체결 결과로 포지션을 갱신합니다.

남은 추천 개선

  1. KisWebSocketBridge에서 시세 REAL 세션과 체결통보 MOCK/REAL 세션을 구조적으로 분리합니다.
  2. DSL 산술 파서에 일반 우선순위 테스트를 추가했습니다. 기존 전략 중 + - * /를 괄호 없이 섞어 쓴 식은 결과가 바뀔 수 있으므로 배포 시 한 번 점검합니다.
  3. 전략 CPU budget은 wall-clock timeout과 별개로 실제 CPU 측정이 가능한 방식으로 다시 설계합니다.
  4. REAL/MOCK 전환 회귀 테스트를 API, consumer, frontend에 시나리오 단위로 더 추가합니다.
  5. 운영 대시보드에 INVALID_ORDER_INTENT, SELL_WITHOUT_POSITION, Redis idempotency 장애 카운터를 노출합니다.
