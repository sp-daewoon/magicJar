P0 CRITICAL

KillSwitch는 사용자가 "전 자동매매 멈춰!"라고 하면 즉시 모든 주문을 차단하는 비상 정지 스위치입니다. ADR 0098 §2-2는 명시적으로 "스위치 정보를 조회할 수 없으면(미등록·DB 오류·예외 발생) 차단(fail-closed)"이 default라고 정했습니다. 그런데 현재 코드는 findById(userId).map { it.enabled }.orElse(false) — 데이터가 없으면 "스위치가 꺼져있다"고 답합니다. 차단이 아니라 통과시킵니다.

시나리오 3. ManualOrderService.kt:153의 ObjectProvider가 빈을 못 찾으면 return으로 스킵 — Spring 컨텍스트 misconfig 시 가드 자체가 무존재화됩니다.

P0-3 · strategy-engine

백테스트 look-ahead bias — 미래 가격으로 평가하고 같은 가격에 체결

P0 CRITICAL
api/src/main/kotlin/kr/spdaewoon/magicjar/api/service/backtest/JvmBacktestEngine.kt:160-256
백테스트의 신뢰성은 "같은 시점의 종가를 평가에 쓰고 즉시 그 종가에 체결"하지 않는 것에서 출발합니다. 실거래에서는 t시점 종가를 본 직후엔 거래가 끝났으니 t+1 시점 시가 이후에만 진입할 수 있기 때문입니다. 현재 엔진은 t의 종가를 슬라이스에 포함시켜 평가하고 동일 t의 종가로 즉시 체결합니다 — 백테스트 학계에서 가장 유명한 self-bar bias입니다.

🚨 현재 (잘못된 흐름)

flowchart TD A[t시점 진입] --> B[safeSlice candles, t] B --> C[t의 close 포함 슬라이스] C --> D[전략 평가: t close 사용] D --> E{BUY 신호?} E -->|YES| F[같은 t의 close × 1+slippage로 체결] F --> G[수익 계산: 인위적 inflate] style C fill:#fff0f0,stroke:#c7363d,stroke-width:2px style F fill:#fff0f0,stroke:#c7363d,stroke-width:3px

✅ 원래 이래야 함

flowchart TD A[t시점 진입] --> B[safeSlice candles, t-1] B --> C[t-1까지 close만 사용] C --> D[전략 평가] D --> E{BUY 신호?} E -->|YES| F[t+1 open × 1+slippage 로 체결] F --> G[수익 계산: 실거래 정합] style B fill:#eaf7f0,stroke:#1d7f5f,stroke-width:2px style F fill:#eaf7f0,stroke:#1d7f5f,stroke-width:3px

⚠️ 이렇게 되면 어떤 문제가 생기나

전략 평가에 "이미 일어난 t의 종가"를 쓰는데 체결도 "그 종가"에 한다면 — 매수 신호가 발생한 순간 이미 그 가격을 알고 있는 셈이라 무조건 그 가격에 살 수 있다는 비현실적 가정입니다.

결과적으로 백테스트 통과율 · 수익률이 구조적으로 부풀어 오릅니다. 그 백테스트가 P0-2 활성화 게이트의 input으로 들어가므로 → 두 결함이 합쳐지면 거의 모든 전략이 활성화 게이트를 통과해버립니다.

// 예: t = 2026-04-15, A종목 close = 1000원 [현재 잘못된 흐름] 평가: "오늘 close 1000원이 SMA 위에 있다" → BUY 신호 체결: 1000원 × (1 + 0.001 slippage) = 1001원 → 시뮬상 1001원에 매수 성공 [실거래] 4월 15일 장 마감 후에는 거래 불가 → 4월 16일 시가 = 1020원 (gap up) → 실제 매수 = 1020원 → 1.9% 손실 출발 (slippage 0.1% 가정과 19배 차이)

🔧 권장 fix

  • safeSlice(allCandles, t) → safeSlice(allCandles, t-1)로 변경 (평가는 t-1까지)
  • 또는 체결을 t+1 open 시점 가격으로 shift
  • 슬리피지 모델 강화: gap up/down 시 시가 적용 + 최대 변동폭 cap
  • 회귀 테스트: 동일 전략 v3.8과 비교해 수익률 1~5%p 하락이 정상 — 그 이상은 의심

⚠️ 이렇게 되면 어떤 문제가 생기나

시나리오. universe = [삼성전자, SK하이닉스, LG에너지솔루션] 3 종목. 전략이 모두 같은 날 BUY 신호를 낸다 가정.

// 실거래 vs 현재 백테스트 결과 분기 [실거래] 1000만원 → 3종목 333만원씩 분산 매수 → 삼성 +5% / SK +2% / LG -3% = 평균 +1.3% (자본 1013만원) [현재 백테스트] 삼성 단독 1000만원 매수 → 삼성 +5% 청산 (cash 1050만원) → SK 단독 1050만원 매수 → SK +2% 청산 (cash 1071만원) → LG 단독 1071만원 매수 → LG -3% 청산 (cash 1039만원) → 백테스트 "수익률 +3.9%" 표시 (실거래 +1.3%와 2.6%p 분기)

🔧 권장 fix

  • outer loop를 종목 → 시간 순서로 transpose: for (t in dates) for (code in universe)
  • 동일 t 다중 신호 우선순위 정책 spec 발행 (architect dispatch): 점수 / 시총 / 알파벳 중 결정
  • cash 분배 모드 옵션화: 균등 분할 / 우선순위 단일 / Kelly criterion
  • portfolio backtest 회귀 테스트 — 단일 vs 멀티 종목 결과 비교
