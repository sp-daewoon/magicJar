## 화면 1 — 케이스 1: 모의 주문 정상 흐름 (/orders 목록)

**URL**: `/orders`

**사전 조건**:
- MAGICJAR_MODE=MOCK 환경
- SettingsModal RealTradingConsentToggle OFF (real_trading_consent_at IS NULL)
- KIS 모의계좌 credential (user_kis_credential.account_type=MOCK) 등록

**화면 구성**:
- 상단: 헤더 "주문 내역" + "MOCK 모드" 배지 (회색)
- 상태 필터 버튼 행: 전체·접수·KIS 접수·부분 체결·체결 완료·거부·취소
- 주문 카드 2건:
  1. 코드: 000660 · 매수 · MOCK 배지 · 10주 · 시장가 → 상태: 접수 (파란 배지)
  2. 동일 주문 → 상태: 체결 완료 (녹색 배지, 완료 시각 표시)
- 우하단 토스트 스택:
  - 파랑 "주문 접수 — 000660 매수 10주"
  - 녹색 "체결 완료 — 000660 10주 @ 75,000원"

**검증 포인트**:
- STOMP REQUESTED·FILLED 토스트 색상 정합 (§16-3)
- 목록 자동 갱신 (invalidateQueries ['orders'])

## 화면 2 — 케이스 2: 3중 게이트 BLOCKED (/orders REJECTED 표시)

**URL**: `/orders`

**사전 조건**:
- MAGICJAR_MODE=REAL + MAGICJAR_ALLOW_REAL=false 환경
- 또는 MAGICJAR_MODE=REAL + MAGICJAR_ALLOW_REAL=true + RealTradingConsentToggle OFF

**화면 구성**:
- 상단: 헤더 "주문 내역" + "MOCK 모드" 배지 (consent OFF 시)
- 주문 카드:
  - 코드: 005930 · 매수 · 10주 → 상태: 거부 (빨간 배지)
  - 거절 사유: "MAGICJAR_ALLOW_REAL=false" 또는 "CONSENT_NOT_GIVEN"
- 우하단 토스트:
  - 빨강 "주문 거절 — 005930: MAGICJAR_ALLOW_REAL=false"

**검증 포인트**:
- KIS prod endpoint(`openapi.koreainvestment.com:9443`) 호출 0건 (자본 보호 LOCK)
- order_audit_event.event_type = REAL_GATE_DENIED 확인
- STOMP REJECTED 토스트 빨강 색상 정합

## 화면 3 — 케이스 3: 분할 체결 /orders/:id 상세

**URL**: `/orders/{id}` (분할 체결 주문 상세)

**사전 조건**:
- MOCK 환경
- 100주 주문 발행
- KisExecutionWsListener H0STCNI9 3건 수신 (50+30+20주)

**화면 구성**:
- 상단 카드:
  - "000660 매수" · MOCK · 상태: 체결 완료 (녹색)
  - 100주 · 시장가
  - KIS 주문번호 표시
  - 완료 시각 표시
- [체결 내역 (3건)] 섹션:
  - 테이블 헤더: 체결 시각 / 체결 수량 / 체결 단가 / 수수료 / 세금
  - row 1: 09:30:05 / 50주 / 73,000원 / — / —
  - row 2: 09:30:12 / 30주 / 73,100원 / — / —
  - row 3: 09:30:18 / 20주 / 73,200원 / — / —
  - footer: 합계 100주 / 100주 (완료)
- [감사 이벤트 (≥4건)] 타임라인:
  - 파란 점: 주문 접수
  - 파란 점: KIS 요청
  - 파란 점: KIS 접수
  - 노란 점: 부분 체결 (×2)
  - 녹색 점: 전체 체결

**검증 포인트**:
- ExecutionTable footer sum = orderQuantity → "완료" 녹색 표시
- 누적 체결량 == 100주 → order_request.status = FILLED
- STOMP PARTIALLY_FILLED 토스트 노랑 × 2회 → FILLED 토스트 녹색 1회

## RealTradingConsentToggle 이중 confirm 화면 구성 (SettingsModal 통합)

**위치**: SettingsModal 내부 "실거래 모드" 섹션

**상태 OFF 구성**:
- 헤더: "실거래 모드"
- 설명: "실거래 모드는 한국투자증권 실계좌 자본을 사용합니다..."
- 토글: 회색 (OFF) + "OFF (MOCK)" 라벨

**토글 ON 시도 → 1차 confirm 다이얼로그**:
- 메시지: "실거래 모드를 활성화합니다. 한국투자증권 실계좌 prod endpoint가 호출되어 실제 자본이 사용됩니다..."

**1차 확인 → 2차 confirm 다이얼로그**:
- 메시지: "재확인: 자본 손실 risk를 이해하고 실거래 모드 동의를 진행합니다..."

**동의 완료 후 ON 상태**:
- 토글: 빨강 (ON) + "REAL ON" 라벨
- 동의 시각 표시 (빨간 텍스트)
- 경고 박스: "주의: 실거래 모드 활성화 상태입니다."
