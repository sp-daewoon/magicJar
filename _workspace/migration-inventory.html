장점 — 코드 자산 100% 보존. 이전 1일 안에 가능.
단점 — 누적된 임시 파일·archive 흔적 일부가 따라옴(필터링 필요).

옵션 B — 레거시 보존 + 신규 작성

이런 경우 적합 — 코드 베이스가 점점 꼬였다는 체감 + 클린 슬레이트 + ADR 0036/0040/0041 등 v2 비전을 처음부터 바닥에 깔고 가고 싶을 때.

실행

  4. 9 컨테이너 docker 표준은 그대로 복제 (ADR 0024)

옵션 C — 현 repo에서 정리만 (이전 안 함)

이런 경우 적합 — 사용자 체감의 "꼬임"이 주로 ADR 번호·archive·tasks 누적이고, 코드 자체는 OK일 때.

실행

  2. tasks open 40건 → done 처리 또는 삭제
  3. devlog는 _archive/로 이동
  4. 스킬 10 → 5 통합
  5. CLAUDE.md 변경이력 분리
  6. v2.1.0 컷 후 다음 사이클
장점 — 가장 빠름. 코드 자산 그대로.
단점 — git history 자체의 누적은 그대로. "꼬였다"는 체감이 다시 올 수 있음.
제 추천 — A안. 사용자가 "ADR 정리 + 다른 repo 고려" 이미 결심한 상태고, v2 베이스라인이 이미 깨끗하게 그어진 시점입니다. 코드는 통째로 들고 가되 메타(ADR·tasks·devlog·archive)만 클린하면 옵션 B의 재작성 비용 없이 옵션 C보다 깨끗합니다.
