magicJar는 **룰 기반 quant trading 시스템**이다. AI는 옵션 보조 기능.

**사용자 인용 (2026-05-02 비전 정정):**
> "차트 기반 종목 발굴 + 진입 신호 + AI 자동 매매가 본질 -> AI가 매매를 하는건 허용하는게 아니다. 신호에 의한이고 AI는 옵션이다 명심해야한다 AI를 접목시킬 수 있는거지 이 시스템에 대한 MCP를 새로 만들어서 활용할 수 있게 하는거지 AI가 메인이 되면 안됨!!"

> "기본 오프라인으로 마스터 데이터만으로도 종목이 추출 가능한 시스템이 기본 목적이고 AI가 해당 추출 종목 및 차트의 지표 여러 분석을 옵션으로 코멘트 밑 기업분석을 목표로함 AI가 그냥 이거 산다 만다의 결정권을 갖는 시스템이 아님"

## 핵심 원칙

1. **시스템 본체 = 룰 기반 quant**: 마스터 데이터 + 지표 + DSL + 시그널 → 자동 주문. **인터넷·AI 끊겨도 작동**.
2. **AI = 옵션 분석 보조**: 사용자 버튼 클릭 시 호출. 종목 코멘트·기업 분석·차트 해석·지표 의미 설명. **매매 트리거 X, 결정권 0**.
3. **MCP 서버 제공이 미래 목표** — magicJar가 MCP **서버**를 외부에 노출. Claude/Cursor 등 AI 클라이언트가 magicJar의 종목·차트·지표·매매일지를 호출. (사용자가 AI를 쓰는 게 아니라 AI가 magicJar를 쓰는 구조)
4. **지표 source는 추상화**: KIS Strategy Builder 80지표는 1차 import. 이후 다른 source(TA-Lib·자체 구현·KRX·추가 라이브러리)도 표준 인터페이스로 가져옴. 지표는 plug-in.
5. **개발 진행 방식**:
   - QA 게이트 배제 (토큰 최소화)
   - 단일 책임 코드
   - API 연동·빌딩은 한 스텝씩 순차
   - **코드 먼저 완성 → 테스트는 데이터 흐름·사용자 시퀀스 기반으로 마지막에 일괄**
   - 테스트하면서 방향 흝으러짐 절대 금지

## 트랙 Wave 구조

- **W1~W3**: 오프라인 베이스라인 본체 (종목 마스터·지표·DSL·백테스트·스크리너·시그널·주문) — 가장 중요
- **W4**: AI 옵션 + MCP 서버 (분석 버튼·기업 분석 코멘트·magicJar MCP server 노출)
- **W5**: 사용자 학습 (사용자와 같이 데이터·아키 의도 검증·일원화)

- 따라서 v0/v1 누적 ADR·legacy 코드·실험적 산출물 모두 정리 후 클린 베이스라인으로 재시작

## How to apply

- 새 트랙·spec·ADR에서 AI를 본체 흐름의 결정 노드로 박지 마라. AI는 항상 사용자 트리거 + 분석 코멘트 산출만.
- "AI가 매수/매도 신호" 표현 자체 금지. 신호 = DSL/시그널 엔진의 룰 평가 결과. AI 호출은 그 신호의 해석·코멘트 생성에만.
- 오프라인 시 fallback 경로 누락 = 비전 위반. 모든 본체 컴포넌트는 AI/외부 API 없이도 동작 검증.
- magicJar MCP 서버는 우리가 client가 아니라 server. 도구 정의는 magicJar 도메인 노출(get_candles·run_screener·get_journal·explain_indicator 등).
- 지표 라이브러리는 source 추상화 인터페이스 위에 KIS·TA-Lib·자체 구현 모두 plug-in.
- 개발 시 테스트 먼저 짜다가 코드 방향 흝뜨리는 패턴 금지. 코드 완성 후 데이터 흐름·시퀀스 기반 테스트.
